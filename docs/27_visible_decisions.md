## 3. 工作项

### K1 · 续约可见化（最高价值，零数值）

**目标**：让 2×/天上线的玩家看见「这次续约锁在了什么价、要不要用免费改签」。

**机制**
- **报告条目补锁价**：`_process_contract_renewals`（`core/game.gd:1186`）写入报告的 `contract_auto_renewed` 条目（`:1200`）增加 `locked_rate`（本次续约锁定倍率）与 `baseline_rate`（该客户当前时代基线）。只加字段，不改既有键与顺序，不改任何结算。
- **值班日志分档**：`data/duty_log.json` 的 `contract` 条目拆为两类：正常续约仍聚合（「续好了 %d 份」）；`locked_rate / baseline_rate < 0.80` 的续约走新条目 `contract_low_lock`（priority 55，高于 contract 的 50、低于 fault 的 60），模板形如「%s 在 %s 期间以 ×%.2f 续约，你有一张免费改签」（机房名、事件名、倍率），双语各 ≥3 变体，同报告多条时聚合为一条并列出机房名。阈值 0.80 写进 `duty_log.json` 的 `settings`，不写死代码。
- **合约面板预告**：机房抽屉合约区（`ui/main_view.gd:1527` 的 `CONTRACT_PROJECTED` 一带，**注意合约区仍在 `main_view.gd`，`datacenter_board.gd` 现在只负责 3×3 舞台**）新增一行「下次续约预计 ×%.2f」，值 = 用**当前时刻**调用 `_locked_rate_for` 得到的折算倍率——与真实续约走同一计算点，只是时间参数不同，因此标「预计」。与当前锁价并排，涨绿跌红。改签确认 sheet（`:4590`）已显示 `CONTRACT_PROJECTED`，新行的口径与它保持一致。
- **待办中心行**：当任一机房 `free_switch_available == true` 且「当前预计锁价 ≥ 当前锁价 × 1.10」时，待办中心出现一行「%d 座机房可免费改签到更好的价」，点击进入该机房抽屉。1.10 也进 settings。免费改签本身的语义、成本、次数**一律不变**。

**新约束（来自批次 0 那批改动）**：预告行会随 HUD 刷新变化，**必须遵守 `construction_rings` 已经立下的纪律——实时更新文本不得触发棋盘/抽屉重建，也不得丢失玩家正在触摸的槽位**。沿用 `datacenter_board.gd` 的 `_state_fingerprint` 思路：只更新该 Label 的 text，不重建容器。

**验收**
1. 单测：矿难 ×0.2 期间自动续约 → 报告条目含 `locked_rate` ≈ 折算值；compose 输出含点名行且机房名/事件名/倍率正确；正常倍率续约不点名；同报告 3 条低价续约聚合为 1 行。
2. 单测：预告值与随后真实续约在**同一时刻**计算的锁价逐位相等（同源证明）；待办行在阈值两侧正反例。
3. 新增断言：预告行刷新 10 次后抽屉节点实例未被重建（沿用 `construction_rings` 的手法），且触摸中的槽位不丢。
4. `midgame_audit` 扩：制造一次低价续约 → 离线弹窗日志区出现点名行 → 待办中心有改签行 → 点击到达机房抽屉 → 抽屉显示预告行。
5. `visual_smoke` 新增双语 `renewal_callout`（日志点名行 + 抽屉预告行同屏）。
6. 20 种子 SHA 逐字不变。

### K5 · 询价还价（唯一数值项，最后一批，可整体去掉）
