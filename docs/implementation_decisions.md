# 实现决策与文档补全

本文只补全原始设计没有给出、但程序必须确定的行为。`00_decisions.md` 仍是产品决策的最高优先级；所有补充值均进入 `data/*.json`，后续可以调平而无需改代码。

## 已采用的首版默认值

| 项目 | 默认值 | 理由 |
|---|---:|---|
| 初始现金 | $40,000 | 首轮模拟发现 $10,000 会永久卡死，$30,000 下纯挂机型仍可能在连续报废后无法重建；$40,000 提供前期现金流缓冲，风险集中到激进扩张阶段 |
| 初始钻石 | 20 | 足够体验少量加速/立修，但不会替代现金经营 |
| 建设队列容量 | 2 | 允许机房与附件并行，避免教学阶段串行等待过重 |
| 毁约费 | 当前机房基础月收入的 10%，最低 $25 | 随规模增长且不会在前期形成硬锁 |
| 行情同类事件 | 不叠加 | 同一客户同一时刻最多受一个专属事件影响；全局事件可叠加 |
| 去广告权益 | 覆盖所有激励广告入口 | 包含欠费救急金；解决 `05_monetization_store.md` 的“三个广告位”与四个入口不一致 |
| 离线上限外支出 | 不扣维护费 | 上限外只推进建设、行情、合约与老化状态；不产生收入、维护费或破产计时，避免长时间离线必然负债 |
| 离线报废 | 冻结于 99.9% | 与设计文档一致；回到前台后才允许进入强制报废 |
| 维护费结算锚点 | 新档创建时间起每个游戏月 | 避免依赖现实自然月和时区 |
| 故障基础率 | 暂按文档公式 0.15 次/柜/月 | 文案中的 1.1 小时期望值与公式相差约一倍；模拟器先以公式为准再调平 |
| 机房环境冷却 | 每格基础 1 点 | 四边覆盖无法触及中心格，而设计又要求低热存储柜放中心；1 点环境冷却使存储柜正常、计算/GPU 仍需外挂 |
| 默认语言 | 跟随系统；中文系统用简中，其余英文 | 发行区域规则与双语需求兼容 |
| 限购礼包边界 | 每个本地账户状态限购 1 次 | 纯单机且无账号/后端，卸载后是新本地身份；每次仍须重新付费，单一 StoreKit 交易不会重复发货 |

## 系统边界

- 美术正式资源由 `art-renders/visual/final/` 交付，经人工确认后通过导入工具复制到 `assets/art/`。游戏代码永不依赖某张图一定存在，缺图时使用程序化占位组件。
- 音乐与音效由 `art-renders/audio/final/` 交付。`assets/audio/manifest.json` 只定义稳定事件 ID；文件缺失时静默跳过。
- 广告与 IAP 通过 provider 接口调用。编辑器和自动测试使用 mock provider；iOS 原生 provider 在最终选定插件后只需完成接口映射，不触碰玩法代码。
- 纯单机、本地存档，不添加后端、云存档、机房网络拓扑或其他 `00_decisions.md` 明确排除的系统。

## 验收口径

- “完整”指 M0–M7 中除正式视听资产生成、第三方后台账号配置、证书签名和 App Store 人工提审之外的代码、配置、自动测试及交付文档全部在仓库内完成。
- 第三方 SDK 未获得最终选型或凭证时，必须有可运行 mock、稳定接口、原生适配模板和清晰接入步骤，不能让核心游戏依赖 SDK 才能启动。
